# 01 · Question sets

Dated 2026-11-26. Every set is a `tests/qa_*.json` file with `cases` (questions with an expected answer)
and `no_answer` (questions that must be declined). Results are from `tests/reports/PROOF.md`.

## What a pass means

Rules from `tests/qa_eval.mjs`; `tests/prove.mjs` applies the same rules check by check.

| Field | A case passes when |
|---|---|
| `id` | The answer is the expected curated answer. A list accepts any of its ids; `a+b` is a combined multi-part answer; `smalltalk` and `moment` (a quoted video chapter) are special answers. A coverage `variant` may add a second answer but must never lose the expected one |
| `must` | This fact appears verbatim (case-sensitive) in the answer text |
| `must_all` | Every rubric point appears in the answer text (case-insensitive) |
| `cite` | This source URL is among the citations, the related cards or the answer itself, and the answer is not a decline |
| `no_answer` | The twin says it has no answer on record (`noAnswer`), with no collage of fragments |
| `prev` | The case is asked as a follow-up after this previous question (rounds 5 and 6) |
| `lang` | The question is in Malayalam, Telugu, Tamil or Hindi (`ml`/`te`/`ta`/`hi`); its `must` fact is in that script, so the answer must come back in that language |

## Where each set runs

- `node tests/integration.test.mjs` runs 14 sets: gold, rounds 2–8, the three interview sessions,
  the held-out set, the language set and coverage. It gates both `ci.yml` and `deploy.yml`.
- `node tests/prove.mjs` runs all 15 (`tests/qa_*.json`). **`qa_research.json` is gated only here**,
  and only in `ci.yml`, not in `deploy.yml` (see [06](06-open-items-next.md)).
- One set alone: `node tests/qa_eval.mjs tests/qa_round5.json` prints `canon x/y · no-answer a/b`
  and each miss with its top three candidates and scores.

## Keeping the sets honest

- Held-out sets are run untuned first and the score is recorded before any fix: rounds 6 and 7
  (81%, 78%) and the interview held-out set (12/15).
- An earlier test is never edited to make a change pass. `GROWTH.md` records this for the PhD change.
- `qa_coverage.json` is generated from the index by `python tests/gen_coverage.py` (after a build). The
  committed file predates the interview and research answers, so it covers 62 of the 163. Regenerated
  at `d9000b7`, it would have 2,874 questions, and 4 of them fail today (see [05](05-findings-and-fixes.md)).
